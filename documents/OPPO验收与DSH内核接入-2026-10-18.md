# OPPO 真机验收与 DSH 内核接入

2026-10-18，接续 [收敛与验收清单](收敛与验收清单-2026-10-18.md)。本轮没有 Redmi，改用 OPPO PDEM30 推进；目标是让 DSH 作为 TermDesk 内核真正可用，并让**正在运行的 DSH 本机会话**能在手机上被看到、点开和接管。

验收环境：Windows 10.0.26200；电脑端 agent 源码 1.0.1-dev.3（未重新构建 APK）；OPPO PDEM30 / Android 13 / 1.0.1-dev.1（versionCode 11）；连接方式为 USB + `adb reverse tcp:7420 tcp:7420` 后的局域网直连（`ws://127.0.0.1:7420`），未使用 Relay。

## 改了什么

1. `pc-agent/src/kernels/asar.js`（新增）：用纯 Node 读 Electron `app.asar` 的索引。头部偏移是实测值（`[4]` 头部 pickle 长度、`[12]` JSON 长度、正文起点 `8 + 头部长度`），并带一个负例测试，避免“偏移错 10 字节却静默读出半个文件”。
2. `pc-agent/src/kernels/dsh-runtime.js`（新增）：解析顺序为 `TERMDESK_DSH` → 独立的 `dsh` 启动器 / npm 元数据 → 桌面安装目录 → 旧 Roaming 目录。归档内的入口用桌面版自带的 Electron 以 `ELECTRON_RUN_AS_NODE=1` 启动——这是唯一能读 asar 的 Node，也是桌面版自己用的那份 24.21.0。
3. `kernels/registry.js` / `manifest.js` / `spawnSpec`：把 `env` 纳入内核描述，保证“发现、控制台展示、真正启动”三者一致；DSH 的 `resume` 从硬编码 `false` 改为按真实能力声明。
4. `ChatManager.resumeDsh`：恢复一个已存 DSH 会话。工作目录取自会话头，模型路由取自本机显式配置；**打开历史只读**，写句柄等到第一条消息才取。
5. 会话标题：优先用运行时自己的 `session/title`，且**以最后一个真实标题为准**（运行时先写一条截断的 fallback，再写模型生成的标题）。
6. `deepseek-account` / `deepseek` 归为“运行时自带的供应商”，不再要求 TermDesk 写覆盖配置。

## 已知边界与下一步

1. **桌面端持有写句柄时无法接管本会话**。这是 DSH 的单写者保护，不是 TermDesk 的选择；关掉桌面端该对话（或整个应用）后，手机“继续对话”才会成功。未在本轮用真实回合验证接管后的第一条消息，因为这需要模型调用许可。
2. **同一会话会出现两行**：一条“可继续”、一条带日期的记录行。前者是本机 chat，后者是日志索引；属于显示重复，不影响读取。去重需要客户端改动，等下一次 APK 构建一起做。
3. 手机打开历史会自动“接管”所有声明 `canResume` 的会话。DSH 已改为延迟取句柄，但**其它内核对“打开即接管”的假设没有重新验收**；下一步应按内核分别确认“打开”是否会写状态。
4. 完整 `npm test` 未在本轮跑完；本轮跑的是 DSH/内核/会话相关的 8 个专项（全通过）。Android 与 APK 未重新构建，手机仍是 dev.1；dev.3 只是源码版本。
5. 恢复后的模型路由来自 agent 的环境变量；会话日志里记录的旧路由没有反推。换机器或换模型时应显式设置，不要靠猜。

## 复现命令

```powershell
# 电脑端（DSH 路由 + 局域网）
$env:TERMDESK_CHAT_PROVIDER='deepseek-account'; $env:TERMDESK_CHAT_MODEL='deepseek-flash'
node pc-agent/src/server.js --host 0.0.0.0 --port 7420

# 手机（USB 调试）
adb reverse tcp:7420 tcp:7420
# 扫码或打开 http://127.0.0.1:7420/pair 后配对，选“远程电脑”

# 只验 DSH 启动，不发模型
$env:TERMDESK_DSH_LIVE='1'; node pc-agent/tools/dsh-runtime-test.js
```
