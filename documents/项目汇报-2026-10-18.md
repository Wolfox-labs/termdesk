# TermDesk 项目汇报

日期：2026-10-18；开发版本：1.0.1-dev.1；已发行基线：v1.0.0。

## 项目是什么

TermDesk 将手机作为 AI 工作的移动入口，将执行交给选定设备上的 Agent 和助手。用户可以在手机上继续会话、回答审批、编辑文件和操作终端，也可以在安装了运行环境后使用手机沙盒。电脑端收敛为代理、设备、助手和会话的管理控制台。

主要价值是把“发起工作、观察过程、确认权限、检查产物”连接成同一条操作链。它不提供模型账号，不替代 Codex/DSH/ACP 助手本身，也不把安装了 App 等同于模型已经可用。

## 已实现到什么程度

| 层面 | 当前交付 |
|---|---|
| 手机 | Kotlin/Compose 原生 App；工作台、会话、文件、终端、系统和设置；配对、草稿与保存确认 |
| Agent | Node.js + WebSocket/HTTP；认证、文件、shell、动态助手发现、会话编排、审批和多端事件分发 |
| 助手 | Codex app-server、DSH SDK、ACP 和 CLI 契约适配；能力和恢复语义按接口分别声明 |
| 本机模式 | 独立 Termux 载荷、校验/解包/健康检查；APK 嵌入 Agent 用内容指纹更新 |
| 桌面 | Compose Desktop 管理器；概览、设备、助手与会话观察，保留运行所有权边界 |
| 可选网络 | TLS 隧道、Relay 配对与反向连接；局域网可独立运行 |

原始方案中的 Flutter、SSH/FastAPI/Docker 主链没有采用；当前选型以 Kotlin、Node 和宿主执行为主。完整架构、数据流与功能限制见[项目说明书](项目说明书.md)。

## 本轮做了什么

三位 GPT-6 Luna 子代理承担主要修复，主代理集成并验证：删除个人模型路由预设；补 Windows PATH/npm 元数据发现；修正宿主工具和窗口约束；使载荷构建输入明确；把审批探针改为可移植的真实断言；在 CI 明确 JDK 21，并为桌面分发带上同版本 Agent。

实际启动时发现桌面精简 JVM 漏打包 java.net.http、java.instrument、jdk.unsupported，导致原生启动器弹出“Failed to launch JVM”。已补齐模块，并新增 [打包预检](../tools/verify-desktop-package.mjs)。修复后先用随包 JVM 无界面加载所需类，再实际打开原生窗口检查页面并关闭；没有将首次构建成功冒充启动成功。

## 仍未完成及风险

1. 手机 Agent 通用配置尚未开放；旧电脑 Codex 配置入口保持隐藏。
2. DSH 配置生成有离线与静态类型依据，未用真实运行时/模型回合认证；本轮模型调用为零。
3. 多电脑缓存/队列仍需完整隔离，多手机独立通知确认未完成。
4. 桌面旧令牌仍被算作手机，危险操作确认及管理文案需继续整理。
5. 工作台目录与终端初始目录尚不统一；大字号、长标题、引用显示和弱网/长期后台还需体验回归。
6. 默认 targetSdk 28 属于侧载运行环境取舍；不是应用商店兼容或恶意代码强隔离方案。
7. 旧 v1.0.0 发行不因本轮修复而自动被替换；新开发分支、实际安装和发行状态分别记录。

## 下一步顺序

先确保桌面分发持续可启动，再完成手机 Agent 配置、设备作用域和通知模型；随后集中做日常交互与分助手认证。每次都保留可复跑脚本、文件落盘证据和明确未测项，避免用页面存在、构建成功或假助手回复代替真实能力。
