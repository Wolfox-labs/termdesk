# 本地沙盒：隔离边界、资源限制与状态展示

> 记录日期：2026-10-06（当日第二轮）
> 设备：vivo V2548A（PD2548）· Android 16 / SDK 36 · arm64-v8a · 8 核
> 应用：`dev.termdesk.app`，targetSdk 28
> 性质：**全部实测**。凡标"实测"的都有命令与原始输出可复跑；未做的明确写出来。

---

## 0 结论速览

| 问题 | 答案 |
|---|---|
| 沙盒有自己的隔离吗？ | **没有超出 Android 应用沙盒的额外隔离。** 它就是 App 的一个子进程 |
| 那它被隔离于什么？ | 其他 App 的数据、`/sdcard` —— 这些是 **Android 给的**，不是 TermDesk 加的 |
| 能阻止用户在终端里读 App 自己的数据吗？ | **不能**（它就是 App），除非改用 proot；见第 4 节 |
| 有内存限制吗？ | **有**，V8 堆上限 512 MB，子进程继承 |
| 有资源回收吗？ | **有**，空闲 45 分钟的对话运行时会自动回收（早于本轮就存在） |
| 本地模式能看性能吗？ | **能**，2026-10-06 起顶栏在本地模式也显示，单位与远程区分 |

---

## 1 隔离模型：同 UID，不是容器

实测（沙盒运行中）：

```
u0_a306   4768  9894  node                  ← 沙盒里的代理
u0_a306   9894  1242  dev.termdesk.app      ← App 进程
        ↑ UID 完全相同
```

代码里搜 `ulimit` / `cgroup` / `setrlimit` / `prlimit` / `namespace` / `unshare`
/ `seccomp` / `chroot`：**零命中**（只有无关的 `import` 字样）。也就是说不存在：

| 机制 | 有没有 |
|---|---|
| 独立 UID / 降权 | ❌ 用的是 App 自己的 UID |
| namespace（pid/mnt/net/user） | ❌ |
| chroot / proot | ❌（沙盒里装了 `proot-distro`，但未启用） |
| seccomp | ❌ |
| cgroup 资源组 | ❌ |
| SELinux 换域 | ❌ 仍是 `untrusted_app` |

**一句话：沙盒不是"盒子"，它是 App 自己的进程树。** 这也是它能执行的根本原因——
Android 从 10 起禁止 App 执行自己数据目录里的文件，targetSdk 28 才落回允许执行的域；
一个真容器反而要绕更多路。

## 2 Android 已经给了什么（不需要我们做）

| 边界 | 由谁强制 |
|---|---|
| 读写其他 App 的私有目录 | Android UID 隔离 —— 做不到 |
| 读写 `/sdcard`（相册、下载…） | App 未申请存储权限 —— 拿不到 |
| 访问系统敏感路径 | SELinux `untrusted_app` 域 |
| 跨 App 注入 / 调试 | Android 沙盒 + 签名 |

也就是说，沙盒**对外**的隔离是实打实存在的（它是 App，App 被隔离）；
缺的是**对内**——沙盒内部各进程之间，以及沙盒与 App 之间的隔离。

## 3 沙盒内部现有的"软边界"（策略层，不是安全边界）

| 位置 | 边界 | 说明 |
|---|---|---|
| 文件 API | `TERMDESK_ROOTS=home;usr` | 文件管理器只能在这两棵树里走；越界路径在符号链接层面校验后拒绝 |
| DSH 自己的工具 | `sandbox/mode = workspace-write` | DSH 的文件/命令工具被限制在工作目录内（DSH 的策略，不是内核的） |
| 内核调用位置 | 每对话一个常驻运行时 | 省得反复起进程；空闲 45 分钟回收 |

**这些是策略，不是安全边界**——它们约束的是"正常调用路径"，
不是"有人故意绕开"。

## 4 为什么不上 proot（备选方案与代价）

想要"看起来像容器"（`cd /` 看到的是容器根而不是手机根），唯一现实的路是
`proot-distro` 跑一个 Debian。不做的理由：

| 代价 | 说明 |
|---|---|
| **不是安全边界** | proot 基于 ptrace 做路径翻译，设计目标是兼容而非隔离；能绕过 |
| 慢 | 路径翻译走 ptrace，实测同类方案通常慢 2–5 倍 |
| 体积 | 需要一份 Debian rootfs（200 MB+），而当前沙盒已经 254 MB |
| 装包仍无稳定方案 | 文档已记：走 docker.io 拉 Debian 在本机网络下超时 |

**结论（本轮的选择）：接受 Android 应用沙盒作为边界，把它写明，而不是做一个看起来更安全、实际不是的东西。**
这正是本项目一贯的做法——宁可说清"这里没有隔离"，也不假装有。

## 5 资源限制

### 5.1 V8 堆上限（2026-10-06 新增）

启动沙盒代理时注入：

```
NODE_OPTIONS=--max-old-space-size=512
```

`NODE_OPTIONS` 会被子进程继承，所以**每个 DSH 运行时也受同一个上限管**，
不只是代理本身。

**实测生效**（在沙盒里问 v8）：

```
$ node -e "console.log(Math.round(require('v8').getHeapStatistics().heap_size_limit/1048576))"
608
```

608 MB = 512 MB 老生代 + 其余空间，与设置一致。

**它管什么、不管什么**：
- 管：V8 的 JS 堆（老生代），也就是失控的 JS 分配
- **不管**：native buffer、以及用户在终端里跑的**非 Node 程序**（那些是自己的进程）

### 5.2 空闲回收（早于本轮就存在）

`pc-agent/src/chat.js`：`IDLE_TTL_MS = 45 分钟`，每分钟扫一次，超时就
`dispose()` 掉该对话的运行时。每个运行时都是一整套 Node harness，不回收会累积。

### 5.3 实测占用（空闲）

```
App 进程     219 MB RSS
沙盒 node     52 MB RSS
设备总内存   11.6 GB
```

## 6 状态展示：数字从哪来

Android 对 App 的可见性比桌面窄得多，实测：

| 想读的 | 结果 |
|---|---|
| `/proc/stat`（系统级 CPU） | ❌ Permission denied |
| `/proc/cpuinfo`（CPU 型号） | ❌ 读不到 → `os.cpus()` 返回空 |
| `/proc/self/stat`（自己进程的 CPU 时间） | ✅ |
| `/proc/self/status`（自己的内存） | ✅ |
| `/proc/meminfo`（设备总内存） | ✅ |
| `/sys/devices/system/cpu/present`（核数） | ✅ `0-7` → 8 |

因此：

| 显示项 | 来源 | 含义 |
|---|---|---|
| 沙盒 CPU% | 自己的进程树 `/proc/<pid>/stat` 的 utime+stime 差值 | 占**单核**的比例（多线程可超 100%，与 `top` 同约定） |
| 沙盒内存 | 同一棵树的 RSS 之和 | 沙盒自己吃了多少 |
| 设备内存 | `/proc/meminfo` | 整机 |
| 磁盘 | 沙盒 home 上 `statfs` | 实测 485 GB 总 / 24.8 GB 可用 / 已用 94.9% |

界面区分（**故意的**）：
- 远程：`内存 61%` —— 电脑整机的占用率
- 本地：`内存 61.2 MB` —— 沙盒自己的 RSS

同一句话里两个数字含义不同，所以单位不同、不混用。

### 6.1 一个踩过的坑

`collectStatus()` 最初在同一轮里**采样了两次**进程树（一次给 `cpu`、一次给 `sandbox`），
两次间隔不到 1 毫秒，差值被放大成荒谬的百分比 —— **实测空闲进程报出 148%**。

现在每次采集**只采样一次**并复用，第一次调用如实返回 `null`（没有基准就没有数字）。
代码里有注释说明，免得以后有人"顺手"再加一次采样。

## 7 复现

```bash
# 沙盒内的进程树与 /proc 可见性（需要 run-as，因为要在 App 身份下跑）
adb shell run-as dev.termdesk.app cat /proc/self/status

# 隔离检查：沙盒进程与 App 是否同 UID
adb shell ps -A -o USER,PID,PPID,NAME | grep -E 'node|termdesk'

# 硬链接是否被禁（Android 的安全策略；这也是 DSH 空回合的根因）
adb shell run-as dev.termdesk.app sh -c 'cd files/home && echo x > a && ln a b; echo exit=$?'

# 堆上限是否生效（在沙盒里）
$PREFIX/bin/node -e "console.log(require('v8').getHeapStatistics().heap_size_limit)"
```
