## 1 打开「设置」会卡死并闪退（已修，真机验证通过）

**现象**：使用者报告"点开设置时 TermDesk 卡得厉害，甚至闪退"。

**证据**（调试机 PDEM30，`dumpsys dropbox --print`）：

```
（主线程）
  at sun.nio.fs.LinuxFileSystemProvider.readAttributes
  at java.nio.file.Files.isSymbolicLink(Files.java:2153)
  at dev.termdesk.app.data.Storage.size(Storage.kt:114)
  at dev.termdesk.app.data.Storage.size(Storage.kt:121)   <- 递归 6 层
  at dev.termdesk.app.data.Storage.inspect(Storage.kt:54)
  at dev.termdesk.app.ui.AppViewModel.loadStorage(AppViewModel.kt:251)
  at dev.termdesk.app.ui.AppRootKt$AppRoot$7$48$1.invoke(AppRoot.kt:247)
  at dev.termdesk.app.ui.CodexSettingsKt$SettingsSection$1$1.invokeSuspend(CodexSettings.kt:90)
```

**根因**：`SettingsSection` 一进入就调用 `loadStorage()`，而 `Storage.inspect()` 在**主线程**上
同步遍历本地内核沙盒。沙盒实测 **72,405 个条目、5,630 个符号链接、约 1.72 GB**
（不是当初以为的 8,302 条 / 242 MB：载荷装进去之后又被装过东西，1.69 GB 都在 `usr/var`）。
主线程走完这么大的树 = 界面冻结 = ANR。

**已做的三处修改**：

1. `Storage.inspect()` 改成在 `Dispatchers.IO` 上跑，主线程永不遍历文件树；
   计算期间界面显示"正在统计…"。清理动作（删除上 GB 的文件）同样移出主线程。
2. 遍历改成**一次 `readAttributes(NOFOLLOW_LINKS)`** 判类型+取大小（原来每个条目要问三次），
   递归改显式栈（深目录不再有栈风险），并且**有界**：沙盒 6 秒 / 40 万条目，
   其它区域 1.5 秒 / 6 万条目；撞到上限会在界面上写"显示的是下限"，
   不会把没数完的数字当成事实。
   注：第一次做的时候上限设成 6 万条，结果给 1.9 GB 的树报了"443 MB"——**没标出来的下限比不报还糟**。
3. 结果缓存 30 秒：重复进设置不再重走整棵树。

**验证**（PDEM30，安装修改后的包）：

- 从点开设置到完整数字上屏 **1.2 秒内**，界面全程可点；
- `StorageUse.truncated` 为 false：1.72 GB / 历史缓存 137 KB / 临时预览 0 B / 已下载 37 KB；
- `dumpsys dropbox` 里最后一次 `data_app_anr` 是 **18:04:52**（改之前的包），
  之后没有任何 ANR 或 crash 记录。

## 3 本地内核投递：已完成的部分与设计决定

- 载荷：`$d/dev.termdesk.app-f-droid-bootstrap-aarch64.tar`（242 MB，8302 条目，1431 符号链接），
- **手机上沙盒的实际体量**（PDEM30 实测）：72,405 条目 / 5,630 符号链接 / 内容合计 1.72 GB，
  其中 `usr/var` 一个目录就占 1.69 GB（apt/dpkg 装过东西留下的缓存与解包内容）。
  这解释了"一个多 G 的历史残余"——它不是历史残余，是装过东西的沙盒；
  想缩小体积应先清 `usr/var/cache/apt`，不是删 `usr`。
  前缀已是 `/data/data/dev.termdesk.app/files/usr`。
- **实测：targetSdk 35 下可以直接执行**（`run-as` 直接跑 `files/usr/bin/coreutils` 成功），
  不需要改 targetSdk、不需要 linker64 包装。
- `.tmp/termux-build/root/` 是 Windows 有损解压（符号链接变 0 字节文件），**不能作为分发源**。
- 方案决定：**打包成 `.tar.gz`**，因为 Android 自带 toybox 的 tar 支持 `-z`，
  手机端可以直接用自己的 tar 解包（符号链接天然正确），客户端不需要引入解压依赖。
- 构建脚本：`pc-agent/tools/build-local-kernel.mjs`（产出 tar.gz + 含 sha256 的清单）。
  注意：该脚本的参数解析有个小 bug（`--version v1` 的值被当成输入路径），下次先修。
- **已完成（2026-10-05）**：
  - 载荷打好了：`~/.termdesk/local-kernel/bootstrap-v1.tar.gz`（**91.5 MB**，比原 tar 小 2.6 倍，
    sha256 `76da67c4…`，8264 条目；符号链接已核对：`bin/cat -> coreutils` 这类相对链接和
    `/data/data/dev.termdesk.app/...` 绝对链接都还在）。
  - 构建脚本修了两个真问题：`--version v1` 的值被当成输入路径；**sha256 算的是输入 tar 而不是产物**
    （手机上校验必然失败——或者说校验了一个不该校验的文件）。产物现在落在 `~/.termdesk/local-kernel`。
  - 代理端端点已就绪：`GET /kernel/local`（清单）与 `GET /kernel/local.pkg`（字节，**支持 Range**）。
    两者都要令牌（401 已验证），中转白名单也加上了这两个路径（VPS 链路同样能取）。
  - 免费回归测试 `tools/local-kernel-routes-test.mjs`（已进 `npm test`，11 项）：401 / 清单字段 /
    区间长度 / **服务出去的字节就是文件本身的字节** / range 头；整包哈希校验用
    `TERMDESK_LOCAL_KERNEL_FULL_HASH=1` 打开（本机实测：下载下来哈希与清单一致）。
- **手机端那一半也做完了（2026-10-05，真机 PDEM30 实测）**：下载 91.5 MB（本机直连约 3.5 s）
  → **sha256 与电脑清单一致** → toybox tar 解包（约 2 s）→ **健康检查真的跑起来**
  （`files/usr/bin/bash -lc 'echo termdesk-local-kernel-ok'` 输出了预期字符串）
  → 设置页卡片显示"已安装 / 占用 / 版本"，失败时给一整句话（不是转圈）。
  实测证据：`usr` 1.9 GB、`var` 1.69 GB 在安装前后一致，条目数 72,405 → 72,438（只增不减，
  说明覆盖式解包没有破坏**另一个 agent 铺的 agent 沙盒环境**）。
- 这一路实测出三个必须记下来的事实（都因此改了代码）：
  1. **App 自己的进程不能执行私有目录里的二进制**：`error=13, Permission denied`。
     之前用 `run-as`（shell 域）测出的"targetSdk 35 也能直接执行"**不代表 App 进程**。
     结论：targetSdk 必须降到 **28**（Termux 自己就是这么做的），已改并写明代价；
     想回到 35 就设 `TERMDESK_MODERN_TARGET_SDK=1`（等于放弃本地内核、其余照旧）。
  2. **toybox tar 拒绝绝对符号链接目标**：载荷里 21 个链接指向 `/data/data/<包名>/files/usr/...`，
     tar 报 `... not under ...` 并退出码 1；用 `/data/data` 这个兼容写法解包也**不行**
     （App 进程看不见那个路径，实测 `exists()` 为假）。做法：tar 退出后按 `tar -tvzf` 的清单
     把缺的链接补成**相对链接**，并且自证（补完逐个检查，缺一个就报错）。
  3. "占用 646 MB"曾是**没数完的下限**（错用了小目录的预算），现在用沙盒预算，与存储页一致。
- **`usr/var` 里那 1.69 GB 不删**（使用者 2026-10-05 明确）：那是另一个 agent 为"本地内核作为
  可选 agent 运行内核"铺的沙盒环境，正是这个功能想要的东西。载荷瘦身因此不再是目标。
- **后续**：把本地内核当"内核"来驱动（`documents/内核接入与通道方案.md` §9 的 ACP 服务端形态）。
  → 跑 `usr/bin/bash -lc 'echo termdesk-local-kernel-ok'` 健康检查 → 设置页入口与进度/失败提示。

## 6 真实模型实测的附带发现（与"模型选择没作用"同源）

跑真实回合时发现的、手机端交互还没做好的地方，记下来免得重复发现：

1. **ACP 的模型清单在第一次发言之前不存在**。PC 端是懒创建内核会话的
   （`sendAcp` 里才 `session/new`），而模型清单来自 `newSession` 的返回。
   所以新建一个 OpenCode 会话时手机端拿到的 `models` 是 0 个——选择器自然是空的。
   修法：建会话时就先创建内核会话（`session/new` 是纯元数据，不调模型、不花钱），
   把 `availableModels` 立刻取回来。
2. **会话详情里的模型选择只对 codex 生效**。`ChatDetailPanel` 写的是
   `if (chat.engine == "codex") codexConfig?.models`，ACP 内核直接落到
   "该内核由自己决定模型与强度"。而 PC 端其实支持逐会话 `chat.config` + ACP
   `session/set_model`（真实回合里就是靠它把模型钉到 `deepseek/deepseek-flash` 的）。
   修法：模型列表统一来自 PC（`chat.models`），不再按内核分叉。
3. 有用的免费工具（本轮新增）：`pc-agent/tools/acp-session-models.mjs opencode deepseek`
   列出某内核新会话能用的模型 id；`tools/acp-model-list.mjs` 走手机协议问同一件事。

## 9 CLI shim：实测记录（QoderWork CN，2026-10-05）

命令：`qoderclicn.exe`（v1.1.26，`%LOCALAPPDATA%\Programs\QoderWork CN\resources\bin\`）。
**免费**就能确认的部分（没有调用任何模型）：

| 事实 | 实测结果 |
|---|---|
| 非交互 | `-p/--print`，提示词是**位置参数**（argv） |
| 输出格式 | `-o` 只接受 `text` / `json` / `stream-json` |
| NDJSON 形状 | `type` = `system` / `assistant` / `result`；`session_id` 在顶层 |
| 回答文本 | 流式在 `message.content[0].text`；末行是 `result.result` |
| 恢复 | `-r/--resume <id>`（还有 `-c/--continue`、`--session-id`、`--fork-session`） |
| 模型 | `-m/--model`、`--reasoning-effort`、`--list-models` → 这个内核的**模型切换是真的** |
| 权限 | `--permission-mode`（default / accept_edits / bypass_permissions / dont_ask / auto）+ `--dangerously-skip-permissions` → 以后"完全权限"在这个内核上是真实开关 |
| 会话清单 | `--list-sessions` 输出的是**人类可读文本**（"No previous sessions found for this project."），按项目分目录（`~/.qoder-cn/projects/<cwd>`）；**本适配器暂不解析**，所以它如实声明"没有可读的会话清单" |
| 登录 | **未登录**：`Not logged in · Please run /login`，退出码 1，错误字段 `authentication_failed` |

因此 manifest 已经从"猜测"改成"实测"：

- 原来猜的 `text: 'text'` 是**错的**（真回答在 `message.content[0].text`）——如果就这样上线，
  手机上会显示一片空白。这正是"用真实 CLI 输出当夹具"的价值。
- 末行的 `result.result` 只在**没流式过**时使用，否则回答会出现两遍（这个项目已经栽过一次）。

**还差一步**：本机 CLI 没登录，所以"真实回答"这一条没验证，`verified` 保持 false → 手机上仍不可选。
用 `qoderclicn login`（或直接在 CLI 里 `/login`）登录后，跑一轮即可翻转。
