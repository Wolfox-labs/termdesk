# 冻结说明 · TermDesk 0.32.1

> 只比 `0.32.0` 多一件事，但这件事是 `0.32.0` 里最不诚实的那个结论的修正：
> **"通知在后台也会出现"当时只在几秒的宽限期内成立。**
>
> 这一版把后台送达做成**可靠**（前台服务 + 唤醒锁 + 手机确认收到），并把这台手机上
> 仍然做不到的那部分（及时送达被系统冻结挡住）如实写在边界里。

---

## 1 为什么会有这一版

`0.32.0` 冻结时的记录是："后台 35 秒，帧到了、也投递了，通知栏确实有。" 那个观测**没错，但条件被漏掉了**：
那一次是在按下 Home 后 **0.8 秒**内到达的帧——那时系统还没冻结这个 App。

这一轮把等待拉长到 60 秒以上，看到的是另一回事：

| 时刻 | 事实 |
|---|---|
| 切后台 | 手机日志：`窗口退到后台` |
| 25 秒后（回合结束） | PC 日志：`notify n-1 turn_done → 客户端在线，直接送出`；TCP 连接仍在（`Established`） |
| 之后 60 秒 | 手机**什么都没有**：没有 `收到`，进程 `isFrozen=false`、`curProcState=4`（前台服务态） |
| 按亮屏幕/回到 App | 手机日志：`收到 n-1`（比 `窗口回到前台` 还早 23 毫秒） |

也就是说：**帧写进了一个仍然开着的 socket，进程被系统挂起，字节一直躺在缓冲里**；
如果这时连接断开（比如 PC 那边重启），这些字节就和连接一起消失，而 PC 早已"送出"并忘记了这条消息。
`0.32.0` 的通知管道在**最需要它的那个场景**里会静默丢消息。

## 2 这一版做了什么

| # | 改动 | 为什么这么做 |
|---|---|---|
| 1 | **手机确认收到（`notify.ack`）** | "写进 socket"不等于"送到"。PC 现在保留每一条通知，**直到手机明确确认**；没确认的在下一次连接时重发。重复发送是安全的：通知 id 由会话派生，重发是**替换**而不是叠加 |
| 2 | **前台服务 `ConnectionService`** | 后台时把进程优先级抬到"前台服务"，这是唯一被支持的"我还在为用户做事"的表达。生命周期：**窗口退到后台且已连接**时启动；**窗口回来或连接断开**时立刻停止；用户在下拉通知里点「不用了」只停服务、不断连接；`START_NOT_STICKY`（自启动会显示一个说谎的"已连接"） |
| 3 | **部分唤醒锁** | 只在前台服务存活期间持有（`onDestroy` 里释放），对付的是**息屏**——口袋里的大部分时间 |
| 4 | **不打扰也要确认** | 正在读那条会话时手机选择不弹，但它仍然回一个 ack：这是**决定**，不是**丢失**；不确认就会每次重连都被重发一遍 |

## 3 验证记录

### 3.1 机器级（可复跑，全部免费）

| 验什么 | 命令 | 结果 |
|---|---|---|
| 通知器的确认语义 | `node pc-agent/tools/notify-test.js` | **26/26**（含"写出去但没确认 → 仍然留着"、"确认一条只忘一条"、"重发只标记一次 whileAway"） |
| 线上真实行为 | `node pc-agent/tools/notify-e2e.mjs` | **全过**（含"没确认的手机下次连接会再收到同样三条"、"确认之后新连接一条都收不到"） |
| 全量回归 | `cd pc-agent && npm test` | **exit 0** |

### 3.2 真机（PDEM30，免费路径：假 ACP 内核，无真实模型调用）

| 验什么 | 证据 |
|---|---|
| 前台服务按时起来 | 切后台 26 毫秒后：`前台服务：窗口在后台且已连接`，`dumpsys activity services` 里 `isForeground=true`、渠道 `termdesk.connection`、id 7432 |
| 唤醒锁确实持有 | `dumpsys power`：`PARTIAL_WAKE_LOCK 'dev.termdesk.app.connection' (uid=10135 pid=18736)`，获取时刻与切后台一致 |
| **可靠**送达（这是本版的重点） | 后台 60 秒期间不处理；回到 App 的**同一瞬间**`收到 n-1`，然后 `投递`/`不打扰`，并把 `确认收到` 发回 PC；PC 记录 `手机确认收到 1 条（还剩 0 条没确认）` |
| 生命周期收尾 | 回到前台后 `dumpsys activity services` 里**没有** ConnectionService 记录（服务已停） |
| 不打扰仍确认 | 正在看那条会话时：`不打扰：正在看这个会话（n-1）` + `确认收到 1 条（n-1）` |

## 4 这一版里如实写明的边界

1. **这台机器上"及时"仍然做不到**：ColorOS（OPPO/一加）在**前台服务 + 部分唤醒锁都持有的情况下**依然把这个 App 挂起
   （`isFrozen=false`、`curProcessState=4`，但代码不跑）。这不是应用层能修的，需要在系统里给 TermDesk 放行
   （设置 → 电池 → 应用耗电管理 → 允许后台运行 / 不优化）。**别的厂商/原生 Android 上前台服务应当就是有效的**，
   但目前只有这一台设备可以验证。放行之后是否变"及时"，还没验。
2. **无 push**：这一版仍然没有推送服务。App 被系统杀掉的期间不会有任何通知，回来时才会补上（并标"你不在的时候"）。
3. **`0.32.0` 的其余边界全部沿用**：装包不能走中转、同一台电脑同时只有一台手机在线、手机离线时解绑不同步、
   Codex 命令行只能看与终止、不是 PTY、`dsh.wolfoxlabs.xyz` 404、没有 MSI 安装包、手机沙盒里没有可对话内核。
4. **B2 的产出文件行仍未被真机点过**（本轮的测试预算用在了通知与前台服务上）。
5. **表驱动帧解析的后半仍未做**；CI 仍未真跑。
