# 本地内核（Termux 沙盒）

> **产品定位**：通用 agent。赛事的数字媒体/AIGC 定位靠包装与话术，不做产品改造。
> **上游**：`移动端agent开发.md` 第二阶段。
> 标记：✅ 已核实 / 🟡 待验证 / ⬜ 待定

---

## 1 形态：应用内下载，不产生独立 APK

载荷是一份 bootstrap 压缩包，解压进 App 私有目录。

| | 应用内下载载荷（本方案） | 外挂 APK |
|---|---|---|
| 系统包管理器 | 不出现 | 必然出现 |
| 设置→应用 | 不可见 | 一定有记录 |
| 安装确认弹窗 | 无 | 需点一次 |
| 桌面图标 | 无 | 有 |

APK 一旦安装即独立包，必被 `PackageManager` 记录，无法隐藏。数据包解压在
`getFilesDir()` 下则仅是应用数据。**下载"应用"做不到隐形，下载"数据"可以。**

与 Termux 官方机制同构：其 bootstrap 也是首次启动解压，本方案只是把
「随 APK 内置」改为「按需下载」。

```
TermDesk APK（唯一安装的应用）
  └─ 首次启动：仅外壳
  └─ 用户点「启用本地内核」
       └─ 下载 termux-bootstrap-<abi>.zip → 校验 → 解压 files/termux/
       └─ 建符号链接 → 写 profile → 换源 → 装包 → 健康检查
```

## 2 双内核

```
                TermDesk 前端壳（Kotlin / Compose）
                            │ chat.*
              ┌─────────────┴─────────────┐
              ▼                           ▼
      本地内核 Termux 沙盒          远程内核 PC Agent
      （可选/按需，脱 PC 可用）      （主力，完整执行环境）
                                    引擎可选：dsh / codex
```

**术语**：`codex` / `dsh` 是远程内核内部的引擎选择，不是与本地内核并列的内核。
产品上只有两个内核。

## 3 约束与解法

> ### 实测补充（2026-10-05，调试机 PDEM30）
>
> 载荷已经**构建完成**，并且在本机上**可以直接执行**，因此 §3.1 的悲观结论需要修正：
>
> | 项 | 实测结果 |
> |---|---|
> | 载荷 | `.tmp/termux-build/artifact.zip`（54 MB）内含 `dev.termdesk.app-f-droid-bootstrap-aarch64.tar.xz`（51.7 MB） |
> | 内容 | tar 8302 条：521 目录 / 6350 文件 / **1431 符号链接**；前缀已是 `/data/data/dev.termdesk.app/files/usr` |
> | 关键程序 | bash、apt、dpkg、proot、proot-distro、python3、node、git、libexec/termux-exec 均在 |
> | ELF 解释器 | `PT_INTERP = /system/bin/linker64`（走系统 linker，不随包分发 libc） |
> | **直接执行** | **成功**：`run-as dev.termdesk.app sh -c 'cd files/usr/bin && LD_LIBRARY_PATH=../lib ./echo hello-direct'` → `hello-direct`（targetSdk 35，未改） |
> | linker 包装 | 不需要；`linker64` 反而要求绝对路径 |
>
> 结论：**不需要 targetSdk 锁 28**，也不需要 linker64 包装就能跑起来。手机里已经有一份解压好的
> 完整沙盒（`files/usr`，含 200+ 库、python3.14、node_modules、terminfo）。
> 缺的是客户端流程：下载/校验/解压/健康检查，以及把它作为「本地内核」暴露给前端
> （见 §4 与 §9）。
>
> 注意：`.tmp/termux-build/root/` 是 Windows 上的**有损解压**（符号链接变成 0 字节文件），
> 只能用来翻看，**不能作为分发源**；分发源是 `artifact.zip` / `.tar.xz`。

### 3.1 execve（决定性）

Android 10 起 targetSdk ≥ 29 落入 `untrusted_app` 域，禁止对应用可写目录
`execve()`。而载荷必须解压后再执行。

| 解法 | 做法 | 评价 |
|---|---|---|
| **A. targetSdk 锁 28** | 保留 `untrusted_app_27` 语义，`execute_no_trans` 允许 | 先用此 |
| B. linker64 包装 | `/system/bin/linker64 <bin>` | A 的后继逃生门 |

### 3.2 前缀硬编码

`com.termux` 硬编码在两层：APK 包名层（本方案不适用）、**bootstrap 内所有
二进制与脚本的 `/data/data/com.termux/files/usr` 路径**（必须处理）。

```
期望前缀：/data/data/dev.termdesk.app/files/termux/usr
```

**因此不能直接用官方 bootstrap**，须自行编译，否则全线 `No such file or directory`。

> 🟡 待验证：能否只改前缀常量做最小重编，而非重编全部预装包。

### 3.3 下载与校验

```
源（优先级）：1 自建分发（Releases/自有服务器）  2 官方 bootstrap（路径重写后）
校验：SHA-256 + 大小；解压前校验，失败重下
传输：>100MB 需分片（Cloudflare 免费版单请求体上限，复用 /upload/session 经验）
```

## 4 镜像源

**默认阿里云，预设多源，失败自动切换。**

```
deb https://mirrors.aliyun.com/termux/termux-packages-24 stable main
```

```bash
sed -i 's@^\(deb.*stable main\)$@#\1\ndeb https://mirrors.aliyun.com/termux/termux-packages-24 stable main@' $PREFIX/etc/apt/sources.list
```

| 序 | 镜像 | 地址 |
|---|---|---|
| 1 | **阿里云** | `mirrors.aliyun.com/termux/termux-packages-24` |
| 2 | 中科大 | `mirrors.ustc.edu.cn/termux/apt/termux-main` |
| 3 | 清华 TUNA | `mirrors.tuna.tsinghua.edu.cn/termux/apt/termux-main` |
| 4 | 官方兜底 | `packages.termux.dev/apt/termux-main` |

```
for src in 候选源:
    apt update（超时 30s）; 成功 → 写入并跳出
全失败 → 提示手动选择 / 检查网络
```

首次初始化**只用 `apt update`，不要 `apt upgrade`**（大量拉包且易中断）。

## 5 首次初始化

```
[1] 下载 bootstrap        进度条 + 断点续传
[2] 校验 SHA-256
[3] 解压 files/termux/    处理 SYMLINKS.txt
[4] chmod +x 关键二进制
[5] 写 profile / .bashrc  环境变量与 PATH
[6] 换源                  阿里云优先，失败切换
[7] apt update
[8] 装预置包
[9] proot-distro 装 Debian（可选）
[10] 健康检查             冒烟命令通过才标记「内核就绪」
```

预置包：`bash coreutils apt termux-tools git python nodejs-lts proot-distro`

**不预装** `clang/make/cmake/autoconf/automake/bison/flex/libtool`——bootstrap
体积与构建耗时的主要来源，AIGC 场景用不上。

**装依赖走 proot-distro，不自建 apt 仓库**：改前缀后官方仓库的包全部不可用
（包内路径写死 `com.termux`），自建整套仓库工作量极大。proot-distro 内是标准
Linux 路径，`apt/pip/npm install` 全部正常。

> 🟡 待验证：proot-distro 在自改前缀下的可用性（社区反馈非 `com.termux` 的 fork
> 装预编译包会失败）。

## 6 保活

**决策：长任务强制前台。** Android 12+ phantom process killer 会杀无 UI 对应的
后台进程树，Termux 场景表现为 **signal 9**。

- 前台服务 + 常驻通知
- wake lock 防息屏中断
- 切后台明确提示"本地任务已暂停"，不静默失败

> 🟡 待实测：前台是否充分。社区经验是必要但未必充分，可能仍需
> `adb shell settings put global settings_enable_monitor_phantom_procs false`。
> 演示前必测。

## 7 影响面与授权

### 7.1 targetSdk（全局影响）

| 项 | 现状 | 本地内核需要 |
|---|---|---|
| targetSdk | 35 | **28** |
| minSdk | 26 | 不变 |
| compileSdk | 35 | 可保持 |

execve 前提，无折中。**是整个 App 降级，不是模块降级。**

> 🟡 待评估：降级对现有 28 个 Kotlin 文件的兼容性影响（权限模型、后台限制、
> 存储访问均有行为差异）。

### 7.2 授权

| 组件 | 授权 | 影响 |
|---|---|---|
| `termux-app` | GPLv3 only | **不涉及**——本方案不分发其 APK |
| `terminal-view` / `terminal-emulator` | Apache 2.0 | 终端渲染可用 |
| bootstrap 内各包 | 各自授权 | 需在提交材料中声明 |

**本方案避开 GPLv3**：触发点是分发 termux-app 程序；此处只分发 bootstrap，
壳自建 + 用 Apache 2.0 终端库。这是相对外挂 APK 路线的实质优势。

## 8 内核切换

```
设置 → 内核
  ├─ 远程内核（默认）    ws/wss → PC Agent
  └─ 本地内核（可选）    未启用时置灰 + 「下载启用」入口

切换：只换执行后端，UI 不变；会话按内核分区；未就绪时给明确状态
```

复用点：`chat.event` 事件种类（`message`/`reasoning`/`tool`/`turn`）与内核无关，
本地内核产出同类事件即可复用渲染层。这是工作量可控的关键。

> ✅ 已实现（2026-10-05，真机 PDEM30）：**手机端执行器** `LocalShell`（`data/LocalKernel.kt`）。
> 一个长驻 `bash --norc -s`（不是每条命令一个新进程，否则 `cd` 与环境全丢），每条命令后打一行
> 哨兵 `__TERMDESK_END__<退出码>|<PWD>`，读出退出码与当前目录、不解析 bash 提示符。
> 终端段顶部多了一个后端开关：**远程内核（这台电脑）/ 本地内核（手机沙盒）**，同一个界面、同一套
> 行模型（`TermLine`），只换执行后端——正是 §8 要的形状。
> 真机实测：`uname -a` → `Linux localhost 4.19.157-perf+ …`；`pwd` → `/data/user/0/dev.termdesk.app/files/home`；
> `python3 -V` → `Python 3.14.6`（都在手机里跑的，电脑不在线也行）。
> 未做：本地**文件/进程**视图仍走电脑；本地内核作为**对话内核**（沙盒里没有 agent 内核，也没有模型）。
> 未测：长任务切后台（§6 的 phantom process killer，L-4）。
