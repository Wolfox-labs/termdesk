# TermDesk 手机端审查与优化执行计划

> 历史材料，保留原规划与当日状态；不代表当前完成度。当前实现、能力边界和目标结构见[架构设计](架构设计.md)、[功能清单](功能清单.md)及[本轮验收](演示版验收-2026-10-17.md)。原文游标增量方案已被本轮按需全量快照方案取代。

日期：2026-10-10
分支：codex/termdesk-audit-fix
目标设备：OPPO PDEM30，1080×2376，override density 510，字体约 1.35 倍

## 已确认的最高优先级问题

1. 首页视觉上选择了可用内核，但新建会话仍可能使用持久化的失效内核 `stub`，导致主流程失败。
2. Android 沙盒的进程和服务采集仍默认调用 `powershell.exe`，采集失败被页面显示成空列表。
3. 文件保存成功后编辑器的 dirty 基线没有更新，可能继续显示“有未保存的修改”。
4. 文件页存在新建文件对话框，但“新建”入口只打开新建文件夹。
5. 系统概览缺少纵向滚动，错误状态、远程连接恢复动作和大字号适配仍需完善。

## 执行阶段

### 阶段一：建立基线

- 记录构建方式、应用版本、Git 状态和关键真机操作路径。
- 保留内核、系统、文件和编辑器问题的复现证据。
- 不改变功能行为。

### 阶段二：修复内核选择和新建会话

- 校验持久化默认内核是否存在且可用。
- 对失效配置回退到当前目标的第一个可用内核。
- 本机和远程目标分开维护默认内核。
- 没有可用内核时禁用新建会话并说明原因。
- 新建会话前做最终校验，确保 UI 选择和实际请求一致。

### 阶段三：修复 Android 系统信息采集

- 按平台选择进程和服务采集实现。
- Android 不再调用不存在的 PowerShell。
- 协议和客户端区分加载中、空列表、失败和不支持。
- 页面提供错误原因和重试动作。

### 阶段四：修复文件状态和文件操作

- 保存成功后更新文本基线、文件大小和修改时间。
- 确保保存后 dirty 状态清除。
- 将“新建”拆分为新建文件夹和新建文件。
- 增加文件名校验和同名错误提示。
- 保留并回归验证未保存修改保护。

### 阶段五：修复页面交互和布局

- 系统概览增加纵向滚动。
- 进程、服务、连接错误提供明确状态和恢复动作。
- 历史会话标题支持两行或展开查看。
- 设置子页返回按钮固定。
- 解绑增加确认。
- 后台运行提示增加系统设置引导。
- 终端首次进入显示连接状态、当前目录和可执行提示。

### 阶段六：大字号和窄屏适配

- 以当前 OPPO 的约 339dp 可用宽度和 1.35 倍字体作为验收环境。
- 测试浅色、深色、键盘弹出、系统返回和底部导航。
- 检查长路径、长标题、长错误、快捷命令和横向滚动。
- 统一控件的选中、未选中、禁用颜色和触控区域。

### 阶段七：验证和文档

- 构建 Android 项目并执行必要测试。
- 重新安装到 OPPO 真机，回归首页、会话、文件、终端、系统和设置。
- 检查 Git diff 和工作区状态。
- 更新 UI 复查文档中的已修复状态。
- 输出修改清单、真机结果、剩余限制和后续建议。

## 验收标准

- 新建会话使用的内核与首页显示一致。
- Android 系统页不再把采集失败伪装为空列表。
- 文件保存成功后显示“已保存”，再次编辑才恢复 dirty 状态。
- 文件页可以创建文件夹和文件。
- 大字号下主要内容、返回操作和错误信息仍然可见且可操作。
- 远程、本机和离线状态均有明确的下一步操作。
