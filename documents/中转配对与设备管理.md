# 中转配对与设备管理

> 这一篇回答两个问题：**手机怎么连上电脑**，以及**谁可以连、怎么把某一台踢掉**。
>
> 写它的直接原因是一次真实故障：`term.wolfoxlabs.xyz` 被两台机器同时声明，同一条隧道的两个连接器被 Cloudflare 分摊请求，手机一半的请求落到了 VPS 上的 relay，扫码配对的结果是 `鉴权失败：invalid credentials`。

## 0 一条主机名只能属于一台机器

Cloudflare 隧道不是"配置里写了就算"：同一条隧道的多个连接器会被**分摊**请求。所以同一个主机名写在两台机器上，就必然出现"有时连到这台、有时连到那台"。任何"两台机器共用一个入口"的做法都是这个结果，和代码质量无关。

结论：**入口只能有一个，机器都躲在它后面。** 这就是中转存在的理由，不是可选项。

## 1 现在的形态

```
手机 ──443/8443──▶ Cloudflare ──▶ VPS
                                   ├─ nginx:8443（TLS，只放行 /termdesk）
                                   └─ relay :7421（鉴权 + 按 nodeId 路由 + 一份手机名单）
                                        ▲
                                        │ 各台电脑主动拨出 wss 连上来
                                        │ （不需要域名、不需要隧道）
```

- 手机只需要**一个地址**。
- 每台电脑用 `~/.termdesk/relay.json` 里的 `nodeId` + key 拨出，relay 按手机所属的节点转发。
- 这台电脑不再跑 cloudflared：`TermDesk.bat` 是 `TERMDESK_RELAY=1`，没有 `--tunnel`。`~/.cloudflared/termdesk-config.yml` 里也删掉了 `term.*`，只留 `dsh.*`。

## 2 配对

在电脑上打开 `http://127.0.0.1:7420/pair`：

- **每打开一次就生成一个新的配对码**，12 位（形如 `ABCD-EFGH-JKMN`），**10 分钟内有效、只能用一次**。
- 手机上用相机扫码即可；摄像头不方便时手输也行——横线、空格随便，`O`/`0`、`I`/`L`/`1` 认作同一个字符。
- 手机拿码换到的是**它自己的凭据**（不是这台电脑的令牌），之后一直用它连接。这台电脑的令牌永远不出门。
- 再加一台手机：重新打开 `/pair` 再扫一次。**一个码只对应一台手机。**

也可以用 `am start` 直接把配对链接投给手机，跳过扫码：

```powershell
adb -s <序列号> shell "am start -W -a android.intent.action.VIEW -d 'termdesk://pair?url=...&token=CODE&name=yaosw&relay=1' dev.termdesk.app"
```

## 3 多台电脑 / 多台手机

| 想做的事 | 在哪做 |
|---|---|
| 加一台电脑 | 在那台电脑上打开它的 `/pair`，手机扫它的码 |
| 换一台电脑 | 手机 → 配对页 → "已配对的电脑"列表 → 切换 |
| 看谁连着这台电脑 | 电脑上 `http://127.0.0.1:7420/devices` |
| 踢掉某一台手机 | 同一页，"吊销这台"——只影响那一台，其他手机照常 |
| 手机自己解绑 | 手机 → 配对页 → 该电脑的"解绑"：本地删记录，同时告诉 relay 删掉它 |

**同时在线的手机数量由 relay 的 `maxClientsPerNode` 决定，默认 1。** 达到上限时新来的一台被明确拒绝（关闭码 4409），手机上显示"这台电脑已有另一台手机在线……它断开后会自动重连"，**不会**把已在线的顶掉。

本项目这台 relay 设成 **2**，因为这台电脑配了两台手机（OPPO + Redmi）：

```json
{ "maxClientsPerNode": 2 }
```

- 想改回"一次只许一台"，把这个键删掉或设为 1，`systemctl restart termdesk-relay`。
- 每多一台在线手机，就是多一个事件流的读者；两台都开着窗口时消息会同时到达两边，这是同一份状态的两次显示，不是重复执行。
- 直连（局域网）那条路没有这份名单：所有手机共用一个令牌，也没有单独吊销。要按台管理，就都走中转。

> 真机上的限制通常不在 relay，而在手机系统的后台策略：手机一进后台就被省电策略掐断连接，另一台才有位置。手机上会提示"系统可能不允许 TermDesk 在后台运行"，需要手动放行后台运行/关闭省电限制。

## 4 凭据放在哪

| 东西 | 位置 | 形态 |
|---|---|---|
| 节点凭据（电脑身份） | 电脑 `~/.termdesk/relay.json` | 明文（本机文件，0600） |
| relay 上的节点/设备/配对码 | VPS `/var/lib/termdesk-relay/config.json` | **只有 sha256**，没有可用的明文凭据 |
| 配对码 | 同上 `pairings[]` | 哈希 + 过期时间；用掉即删，过期即废 |
| 手机凭据 | 手机 Android Keystore | 每台电脑一条，AES-GCM 加密，密钥不可导出 |

配对码上限：每台电脑同时最多 5 个待用码（防呆，不是安全边界）。

> 注意这个上限的副作用：`/pair` 每打开一次就占一个名额，agent 每次启动也会印一个。**堆满 5 个之后，`/pair` 不再报错，而是静默退化成"局域网直连 + 配对令牌"**——页面上连接地址变成 `ws://<局域网IP>:7420`、标签从"配对码"变成"配对令牌"，就是这个状态。等 10 分钟自然过期，或把 `config.json` 的 `pairings` 清空后重启服务。

## 5 运维

| 东西 | 位置 |
|---|---|
| relay 代码 | VPS `/opt/termdesk-relay/src/`（与仓库逐字节一致） |
| relay 数据 | `/var/lib/termdesk-relay/config.json`（`termdesk` 用户，0600） |
| 服务 | `termdesk-relay.service`（听 `127.0.0.1:7421`） |
| nginx | `/etc/nginx/conf.d/termdesk-relay-site.conf`、`/etc/nginx/termdesk-relay-locations.conf` |
| 日志 | `journalctl -u termdesk-relay`、`/var/log/nginx/termdesk-relay-access.log` |
| 上服务器 | `ssh oulucloud`（直连，不用代理） |

部署一次改动：

```bash
scp relay/src/relay.js oulucloud:/opt/termdesk-relay/src/relay.js
ssh oulucloud 'systemctl restart termdesk-relay'
```

改配置（例如放开第二台手机）：

```bash
ssh oulucloud "python3 -c \"import json;p='/var/lib/termdesk-relay/config.json';d=json.load(open(p));d['maxClientsPerNode']=2;json.dump(d,open(p,'w'),ensure_ascii=False,indent=2)\""
ssh oulucloud 'systemctl restart termdesk-relay'
```

relay 现在会为每台手机和每台电脑记一行，手机说"连不上"时先看这里：

```
[relay] computer termdesk-pc-309391514336 connected
[relay] phone 006d2edc-… online (1/2, node termdesk-pc-309391514336)
[relay] phone 006d2edc-… offline
```

## 6 验收命令

| 验什么 | 怎么验 |
|---|---|
| 公网健康检查 | `curl -s https://termdesk-oulu.wolfoxlabs.xyz:8443/termdesk/healthz` → `{"ok":true,"service":"termdesk-relay"}` |
| 电脑这一端在中转上 | 电脑 `http://127.0.0.1:7420/status.json` → `relay.connected: true`；`journalctl` 里有 `computer … connected` |
| 手机是在走中转而不是直连 | VPS `journalctl -u termdesk-relay` 出现 `phone … online (n/2)`；同时把 `adb reverse --list` 清空后手机仍显示"已连接" |
| 手机换到了中转 | 手机应用私有目录 `shared_prefs/termdesk.xml` 里 `activeComputer` 指向 `relay:true` 的那条，`url` 是 `wss://termdesk-oulu…` |
| 公网整链（配对 → 鉴权 → 真实请求 → 文件上下行 → 解绑） | `cd pc-agent && node tools/relay-public-check.mjs`（13 项） |
| relay 自身（出码 / 一次性 / 名单 / 吊销 / 越权 / 多手机上限） | `node --test relay/test/relay.test.js`（14 项） |
| 隧道连接器 | `cloudflared tunnel info termdesk` → `term.*` 这条隧道**不应**再出现这台电脑的连接器 |

## 7 已知边界

- **装包不能走中转**：relay 只转发已配对手机的 `/download` `/upload`，未配对的手机拿不到 APK。装/升级走局域网（`http://<电脑IP>:7420/app.apk`）或 adb。
- **同一台电脑同时在线的手机数受 `maxClientsPerNode` 限制**（默认 1，本项目 2）。手机进后台被杀断开会腾出位置，这不是 relay 的问题。
- **直连路径没有单独吊销**：局域网直连仍是一个共享令牌。中转路径才是按台管理的。
- **`dsh.wolfoxlabs.xyz` 现在没有本机入口**：cloudflared 已不在本机运行，那条隧道只剩 VPS 一个连接器，而 VPS 的 ingress 只写了 `term.*`，所以该地址目前是 404。要恢复它，得给它**单独一条隧道**（同一条隧道两边都挂连接器就会重演本文开头那件事）。
