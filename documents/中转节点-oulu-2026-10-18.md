# Oulu 中转接入验收 — 2026-10-18

> 目标：手机**不再依赖 adb**（USB 反向转发 / 无线调试）也能连上这台电脑，改由 oulucloud 上的 relay 作为唯一入口。
>
> 结论：**做到**。两台手机（OPPO PDEM30、Redmi 25102RKBEC）都已在删除 `adb reverse` 之后通过 `wss://termdesk-oulu.wolfoxlabs.xyz:8443/termdesk` 连上；同一台电脑同时在线的手机上限已从写死的 1 改为可配置，本项目设为 2。

## 1 部署了什么

| 项 | 值 |
|---|---|
| 服务器 | oulucloud `172.247.44.74`（`ssh oulucloud`，端口 23456） |
| 域名 | `termdesk-oulu.wolfoxlabs.xyz`（Cloudflare 代理开启，A 记录指向该 IP） |
| 对外入口 | `wss://termdesk-oulu.wolfoxlabs.xyz:8443/termdesk` |
| TLS | nginx 1.26.3，`listen 8443 ssl`，Let's Encrypt 证书 |
| 反代 | `/termdesk` → `127.0.0.1:7421`，非 Cloudflare 来源 403 |
| relay | `termdesk-relay.service`，`/opt/termdesk-relay/`，只听回环 |
| 数据 | `/var/lib/termdesk-relay/config.json`（`termdesk:termdesk` 0600） |
| 节点 | `termdesk-pc-309391514336`（这台电脑，`~/.termdesk/relay.json`） |

电脑端以 `TERMDESK_RELAY=1` 启动 agent，主动拨出到 relay；手机只认这一个地址。

## 2 代码改动

`relay/src/relay.js`：

1. **`maxClientsPerNode`（默认 1）** —— 原来写死"一台电脑只许一台手机在线"，第二台一律 `close(4409)`。现在由部署配置决定上限，默认行为不变。
2. **三行运维日志** —— `computer … connected` / `phone … online (n/max)` / `phone … offline`。手机说"连不上"时，先看这三行能区分"没到 relay"、"被上限拒绝"、"连上又掉了"。
3. 拒绝时也记录当前连接数，例如 `phone … refused: 2/2 already connected`。

`relay/test/relay.test.js` 增两项：默认拒绝第二台、配置为 2 时两台同时在线且拒绝第三台。全套 **14 项通过**。

## 4 真机上遇到的三个问题

1. **第二台被拒（4409）**：不是网络问题，是 relay 的写死上限。已改为配置项（见上）。
2. **`/pair` 静默退化成"局域网直连"**：每台电脑最多 5 个待用配对码，`/pair` 每访问一次就占一个、agent 启动也印一个；堆满之后不再报错，只是页面从"配对码"变成"配对令牌"、地址变成 `ws://<局域网IP>:7420`。清空 `config.json` 的 `pairings` 后恢复。
3. **手机进后台就断**：ColorOS/HyperOS 的省电策略会掐掉连接，App 自己也提示"系统可能不允许 TermDesk 在后台运行"。这不是 relay 的问题；两台手机之所以"轮流在线"，是因为另一台在后台被掐断了。要真正常驻，需要在系统里放行后台运行/关闭省电限制。

## 5 还没做

- 桌面控制台"设备"页里 24 条历史记录大多是调试期留下的，需要按台清理（relay 侧另有 6 条测试设备记录）。
- 手机安装包仍只能走局域网或 adb（relay 只转发已配对手机的 `/download`、`/upload`）。
- 版本：本轮把 agent 版本推为 `1.0.1-dev.4`，桌面安装器随之重打；手机 APK 仍是 dev.3（未重装）。
