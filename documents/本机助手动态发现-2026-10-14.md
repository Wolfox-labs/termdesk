# 本机助手动态发现 · 2026-10-14

用户反馈：本机选择器混入了固定候选目录中的 Codex、OpenCode、MiMo、Qoder、Command Code、Antigravity 和豆包等未部署项。

本轮修复：

- 本地代理的 kernels.list 由实际检测结果生成，仅返回发现已安装的内核；保留远程电脑的安装诊断目录。
- 解析当前 PATH、显式执行路径、运行时与脚本路径；不存在的覆盖配置不能再制造 available=true。POSIX 校验执行权限，拒绝把复制的 Windows PE 文件当成本地可执行程序。
- 对 Node 托管的 DSH SDK 检查 Node 和可读脚本，不错误要求 JS 脚本具有执行位。
- 每次请求重新检测；接入配置目录 ~/.termdesk/kernels/*.json 可登记任意 ACP/CLI 助手，无需改品牌名表。JSON 沿用环境接入字段 id、label、bin、preArgs、args；CLI 额外指定 transport=cli 及既有 shim 契约。只有对应文件/命令实际存在才会出现在本地列表。
- 客户端对旧本地代理返回的未安装候选项做兼容过滤；打开选择器自动刷新，增加“重新检测”，标题区分本机/电脑。

验证：

- 动态发现专项：Windows 上 5 项通过、1 项 POSIX 专用检查跳过；随后在 OPPO 沙盒 Node v24.18.0 内补跑，6/6 全部通过、无跳过，包含执行权限与 Windows PE 拒绝检查。
- 注册表 34/34、本机模式 16/16；完整 npm test 退出码 0。
- Android 构建与单测成功，现有 106 项单测保持通过。
- 已覆盖安装 USB OPPO；当前“选择本机助手”实际仅显示 DeepSeek Harness，以及重新检测/完成，没有 7 个未安装项。
- 未调用模型，没有安装任何新的助手。接入配置测试用临时目录和脚本，验证新增、移除及未知名称；没有替用户新增永久接入配置。
- 已保留当前选择器打开，方便用户直接查看。

说明：发现可执行入口与接入协议不等于验证了账号、模型服务或每个新程序的运行兼容性。已有协议适配描述仍保留；列表展示依赖本机部署检测结果，未按品牌维护隐藏名单。
