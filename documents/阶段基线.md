## 2 交互方向（已确认）

1. **主页是落地页**：打开 App 先看到主页——连着的电脑、当前内核、项目与工作目录、最近会话、快捷入口（新建/文件/终端）。
2. **内核切换放主页**，新建会话不再问内核。
   （现状：设置里的内核页与新建会话各写了一套界面代码，数据同源但 UI 重复；统一到主页这一处。）
3. **权限一次选到底**：要能选"完全权限"这类持久选项，而不是每轮都点一次。
   输入区布局对齐成熟 agent 应用：一行内放下 `＋`（文件/指令）、权限、模型 + 推理等级、发送/停止。
4. **分栏可以有**，前提是能收起、能展开；另有"栏目"形态——覆盖屏幕内容、不挤占主区（会话页现在就是这个形态）。
5. **会话与文件打通**：在会话里能直接看到工作目录、直接进该目录、直接打开这一轮产出的文件；终端同理。
   现在只能从任务/会话列表绕进去，等于没有。
6. **接管电脑上已有的会话**：现在只能在手机上新起任务，无法续接电脑上正在跑或已有的任务，这是"远程全流程"真正的缺口。
   目标：手机能接上电脑上现有的任务继续推进，而不是每次从零开始。

## 3 技术方向（已确认）

- **通道只有一条：WebSocket。** 不引入 SSH。理由：一条认证、一套协议、穿过 Cloudflare 隧道不需要额外端口；
  SSH 真正独占的能力只有端口转发与天然 PTY——前者隧道能做，后者可以在代理侧用 ConPTY 补，不必为此再养一套身份与客户端。
  Docker 不用（用下来不值），统一交互路线。
- **域名收敛到 term**：现在 `term.wolfoxlabs.xyz` 给手机 App、`dsh.wolfoxlabs.xyz` 是 DSH 桌面端 Web UI 的浏览器兜底通道。
  既然已经有手机 App，这条兜底通道的存在感很低，两个域名应该统一到一个标准入口（保留还是关掉、怎么分流，见第 6 节）。
- **大单文件拆包**：`chat.js`(78 KB)、`AgentClient.kt`(88 KB)、`ChatSection.kt`(73 KB) 按职责拆分，保持架构化和可维护性；重构随后安排。
- **CI**：目前只有本机 `npm test`（一套零模型调用的静态/桩测试），重构时补上自动化流水线。
- **版本协商**：在冻结版本时一并处理，现在不做。
- **离线能力 = 指令排队补发**：断线时输入不丢，恢复后按序补发。这条要做（其它"离线缓存"不重要）。
- **长任务保活不是问题**：任务不跑在本地，中间断联多少次都无所谓，只要能发出去一次、能收到一次结果；
  只有"跑在本地沙盒里的东西"才涉及保活。
- **不做**：自研小模型、本地轻量模型（没有这个需求）。
