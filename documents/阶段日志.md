## 阶段 2 · 2026-10-06（DSH 不能对话：根因与修复）

### 一句话
使用者报"DSH 内核下无法对话"。根因不在手机、也不在协议，而在 **DSH 自己的配置分层**：
`~/.dsh/settings.yaml` 已不存在，provider `wolfox` 只剩在**桌面 profile 的 patch** 里，
而 TermDesk 驱动的是 `--profile sdk`——后者不读它，于是握手被拒，一轮都没开始。
已用 DSH 自带的 `--patch` 机制修好（TermDesk 自己写覆盖配置），并端到端跑通一次真实回合。

### 证据（先用免费手段定位，再花一次调用验证）
| 步骤 | 结果 |
|---|---|
| `dsh --profile sdk --dump-config` | 无 wolfox；`agent-default-model` 退回 `deepseek-official/deepseek-v4-flash` |
| `dsh --profile desktop --dump-config` | 有 wolfox（端点 + `apiKeyEnv` + 模型表） |
| 读 `dsh-settings-file` 源码 | 读 `~/.dsh/settings.yaml`；该文件**已不在**（只剩 `settings.yaml.bak-*` / `.imported`） |
| 只握手的探针（零调用） | `initialize -> -32603: no adapter registered for provider "wolfox"` |
| 加了覆盖配置后的探针（零调用） | `initialize -> ok`（`deepseek-harness-sdk-runtime`） |
| 手机同款帧走完一轮（1 次授权调用） | `chat.create engine=dsh` → `chat.send` → `[message/assistant] OK`，`turn ended · completed` |

### 改了什么
- 新增 `pc-agent/src/kernels/dsh.js`（路由 + 覆盖配置生成），产物 `~/.termdesk/dsh/sdk-overlay.yml`，
  **不写 `~/.dsh`**。
- `pc-agent/src/chat.js`：路由单一来源；`dsh --profile sdk --patch <overlay>`；
  解析不了 provider 时错误里写明该设哪个环境变量。
- 新增免费测试 `pc-agent/tools/dsh-profile-test.js`（20 项，已进 `npm test`，全绿）。

### 下一步
- **要重启电脑端实例**（7420 跑的是旧代码）才在手机上看到效果 → D3。
- DSH 若改走 `--profile acp`（它自带 ACP 服务端），就能与其它 ACP 内核共用一条适配器，
  并补上 native 路径缺的"取消 / 历史恢复" → C5 待定。

## 阶段 3 · 2026-10-06（本地内核 = 沙盒里的同一个代理）

### 一句话
"本地内核"不再是一套手机专属实现：沙盒里跑的就是 **PC 上那份 TermDesk 代理**（同一份 Node 源码，
随 APK 打包，由 Gradle 任务从 `pc-agent/src` 同步）。于是文件、终端、系统、会话全部走**同一条协议、
同一套客户端代码**，手机端只换 socket —— 这正是使用者要的"沙盒当第二台电脑"。

### 真机证据（PDEM30，零模型调用）
| 步骤 | 结果 |
|---|---|
| 设置 → 内核 → 本机 | 代理解包（46 个文件）→ `local agent ready on port 7431` |
| 代理自己的横幅 | `监听 127.0.0.1:7431（只在本机回环）`、`目录 files/home  files/usr`、`公网 不适用` |
| 代理的内核表 | 8 个内核全部"未在本机找到"，`手机上可选：（无）` —— 沙盒里确实什么都没装 |
| 文件 | 根目录是 `/data/user/0/dev.termdesk.app/files/home`，列出 `.termdesk` / `.termux`（沙盒自己的文件） |
| 终端 | `sh1 · bash`；点"uname" → `Linux localhost 4.19.157-perf+ … aarch64 Android` |
| 对话 | 如实说：`沙盒里还没有可用的 agent 内核：装上 opencode / dsh 之类任何一个，会话就能在这里跑起来` |

### 改了什么
- PC 侧：`server.js` 新增 `--local`（只回环、无配对页、无隧道/中转，且`ensureTunnel` 直接拒绝）、
  `terminal.js` 新增 POSIX 分支（bash + 与 PowerShell 同一套哨兵协议）、`files.js` POSIX 根目录、
  `registry.js` 在 POSIX 上按 PATH 找内核、`pair.js`/`relay-client.js` 的重依赖改为按需加载。
- 免费测试新增两个：`tools/terminal-posix-test.js`（11 项）、`tools/local-mode-test.js`（15 项，
  完整走一遍"非桌面宿主机"：回环监听、无配对页、文件、bash、内核表诚实）。`npm test` 全绿。
- 手机侧：`LocalAgent.kt`（从 assets 解包 + 起停 + 就绪判定 + 令牌读取）、
  `AgentClient` 去掉本地终端那条**平行实现**（LocalShell 已删）改由 socket 切换、
  `AppViewModel` 在开关处负责连接、`TerminalSection` 不再只为远程开会话。
- 顺带修掉一个真问题：`对话` 那一页的"本地内核"提示是**全屏且没有顶栏**的，进去就出不来（抽屉打不开）。
  现在外壳在这种情况下自己画一条栏，且提示写的是真实原因。

### 下一步
- 沙盒里装一个 ACP 内核 → 会话在本地真正可用（要网络与模型，等你点头）。
- 长任务保活（前台服务）：现在只有"约 1 分钟后台"的实测。

## 阶段 4 · 2026-10-06（DSH 装进手机沙盒）

### 一句话
本地内核第一次有了**可对话的东西**：DSH 在手机沙盒里跑起来了（代理识别 → 建会话 → 运行时就绪）。
路上两个平台卡点（node-pty 没有 Android 预编译、koffi 需要按 android 平台安装）都已解决，并做成
可复现构建。**但那一轮仍然什么也没返回**，已经排除网络/凭据/模型，问题在 DSH 自己的回合内。

### 证据（免费手段优先，真实调用 3 次极小）
| 检查 | 结果 |
|---|---|
| 直接跑 DSH（沙盒） | 先失败：`node-pty` 找不到 `prebuilds/android-arm64/pty.node`；`koffi` 找不到原生模块 |
| 换成 android 目标安装 + 管道替身 | 握手成功：`{"serverInfo":{"name":"deepseek-harness-sdk-runtime"}}` |
| 代理的横幅 | `✔ DeepSeek Harness native`，`手机上可选：DeepSeek Harness` |
| 手机建会话 | 转写："运行时已就绪（原生会话）" —— 代理写好覆盖配置、拉起 DSH、握手成功 |
| 手机发一句 | **只有 started/ended，没有回答、没有错误** |
| 沙盒里直连模型 API | `mimo-v2.6-flash` 与 `spe/deepseek-v4.1-flash` 都返回 `content="OK"`（流式同样） |

### 改了什么
- `pc-agent/kernels/dsh-sandbox/node-pty-shim/`（新）：管道版 node-pty，注明**没有 TTY**。
- `pc-agent/tools/build-dsh-sandbox.mjs`（新）：可复现构建 + 自检（android koffi、替身、入口），
  产出 34.3 MB 载荷与 sha256 清单。
- `LocalAgent.kt`：注入 `DSH_HOME`/`TERMDESK_DSH`、把 `.credentials.yaml` 的 key 放进代理环境
  （provider 行写的是 `apiKeyEnv`，没人放环境变量就是静默 401）、沙盒默认走免费模型。
- `chat.js`：DSH 空回合不再沉默。

### 下一步
- 找出 DSH 回合为空的原因。最大嫌疑：我们那份覆盖配置里模型行缺 `reasoningEfforts`/`compat`，
  而默认模型是推理模型。其次是开 DSH 自己的请求日志。
- 之后才是数媒那条线（媒体工具链：apt 走不通 —— 官方 Termux 包写死 `com.data.termux` 路径，
  实测 `error creating directory './data/data/com.termux': Permission denied`；proot-distro 的
  Debian 走 docker.io，手机网络超时。**静态二进制 + 由 PC 侧分发**是更现实的路，
  已下好一份 arm64 静态 ffmpeg 备用）。
