# 多端联动修复与 Redmi 复验

日期：2026-10-17。分支：`codex/termdesk-audit-fix`。版本：`0.33.0-demo.3`，Android versionCode `9`。

**结论：本轮已修复并验证事件被桌面抢走、在线吊销不生效、手机运行环境状态误判及回合标记泄漏原始状态四项问题。桌面管理控制台的其他体验待办仍保留，不据此宣布整体验收完成。**

## 修复内容

| 问题 | 当前行为 |
|---|---|
| 后连接桌面替换手机接收者 | 服务端维护已认证连接集合，会话事件同时送达；一个观察端断开不会取消其他端的接收 |
| 列表或控制权状态不同步 | 按每个接收者计算 ownership，状态与接管变更更新列表；客户端同步正在查看的会话摘要 |
| 桌面消费手机通知 | 桌面不接收或确认手机通知；没有手机接收时仍暂存并补发 |
| 终端输出接收者被替换 | 普通终端按连接当前打开的 session 分发；会话终端按各连接的订阅分发 |
| 吊销只在下次认证生效 | 按服务端验证的凭据记录断开该设备的所有连接，在 close 握手完成前即停止接受操作；移除同样生效 |
| 新配对只能使用 WebSocket | 文件与运行环境 HTTP 接口接受有效设备凭据，吊销后拒绝后续请求；旧主令牌兼容保留 |
| 桌面目标 ID 当作设备身份 | 连接目标与持久化桌面身份分开；只读会话的“结束会话”禁用，服务端写入守卫保留 |
| 电脑离线被显示成安装失败 | 在后台先检查手机实际安装，安装包信息读取错误独立显示；初始检查期间不显示“未安装”或开放安装按钮 |
| “完成 · ended”及生硬认证错误 | 回合状态使用中文标记，未知状态不假报成功；吊销显示“此设备的连接权限已被撤销，请重新配对” |

## Redmi 实际复验

设备：REDMI K90 Pro Max，型号 `25102RKBEC`，系统报告 Android 17 / API 37，保留原 1.45 倍字号。

使用独立的临时配对、回环测试代理与固定回复助手，通过无线调试的 ADB reverse 转发连接。电脑端使用后台协议观察客户端，**没有再次打开桌面原生窗口或抢占电脑界面**。因此本轮验证的是手机与桌面协议的联动，不等于公网、中转或最新桌面窗口的完整交互验收。

| 场景 | 实际结果 |
|---|---|
| 手机单独发送 `FIXED_BASELINE` | 收到第 1 次固定回复 |
| 后连接后台桌面观察端，手机发送 `FIXED_WITH_DESKTOP` | 手机不离开会话即显示第 2 次回复；观察端记录 12 条事件、1 次回合结束、0 条手机通知 |
| 关闭观察端后发送 `FIXED_AFTER_DESKTOP_EXIT` | 原手机连接继续显示第 3 次回复 |
| 查看回合边界 | 显示“已完成”，没有“ended” |
| 撤销临时手机凭据 | 返回成功后手机立即显示断线；设备页显示权限已撤销，无需重启 App |
| 电脑不可达时进入设置 | 手机运行环境显示“已安装”；安装包读取错误独立显示，不再显示“安装失败” |
| 设置导航与配置入口 | 设置及子页不显示底栏，电脑 Codex 编辑入口保持隐藏 |

联动复验后补齐了会话摘要字段同步，再次执行 Android 单测及构建，并覆盖安装最终产物。上表联动行为未在最后一次小改动后完整重跑；最终包身份已另行核对如下。
