## 必须先修复

### P1：桌面连接会抢走手机的实时事件

实际复现：先连接模拟手机，再连接模拟桌面观察端，由手机发起合成回合。手机收到 `chat.event` **0 条**，桌面收到 **12 条**。当前已连接的桌面窗口也不会自动获得另一连接创建的会话，需要手动刷新。

原因：[server.js](../../../pc-agent/src/server.js) 认证后覆盖 `routedSocket`，并重新调用 `chats.attach` 和 `notifier.attach`；[chat.js](../../../pc-agent/src/chat.js) 只有一个事件接收者。桌面作为管理观察端时，不能占用手机的输出通道。最后连接关闭后也不会自动恢复之前的接收者。

验收要求：事件按订阅广播，写入仍按 owner 控制。手机持续收取正文时打开或关闭桌面，手机事件不丢失；桌面列表和状态同步更新。通知及终端通道也要单独核查。

### P1：吊销只影响下一次认证，现有连接仍可操作

实际复现：配对并认证一个模拟手机，管理员执行 `devices.revoke` 返回成功。原手机连接仍为 OPEN，继续请求 `kernels.list` 得到清单；之后仍成功创建并发送了合成会话。

[devices.js](../../../pc-agent/src/devices.js) 仅修改登记状态；[server.js](../../../pc-agent/src/server.js) 在首次认证时校验凭据，没有在吊销时关闭该设备的现有连接。[ConsoleDevices.kt](../../../desktop/src/main/kotlin/dev/termdesk/desktop/ui/ConsoleDevices.kt) 却写着“吊销会立即拒绝这台手机”。

验收要求：吊销和删除使对应设备的现有连接立即失效，同时拒绝新连接；其他设备继续工作。补服务端真实 WebSocket 用例，注册表单测不能代替这一层。

### P1：桌面身份被运行目标 ID 覆盖（代码核查）

[WorkbenchStore.kt](../../../desktop/src/main/kotlin/dev/termdesk/desktop/workbench/WorkbenchStore.kt) 已生成持久化 `desktopDeviceId()`，但 `connect(deviceId: String = activeDeviceId)` 的参数同名遮蔽该字段，传给 `AgentSocket` 的实际是运行目标 ID；本机通常为 `local`。

这使不同桌面实例可能使用相同客户端身份，影响主控判断。此项由源码确认，本次未启动两个桌面实例验证。

验收要求：连接目标 ID 与客户端身份分开命名；认证始终传稳定的客户端身份，并补两个桌面客户端的控制权测试。

## 管理体验问题

| 优先级 | 问题与证据 | 建议 |
|---|---|---|
| P2 | 未配对手机时，仅桌面通过主令牌连接就显示“1 台有效手机”；该条实际是 legacy 主令牌 | 将旧凭据与手机设备分开统计，未配对显示 0 台；状态区分在线、离线、待配对和已吊销 |
| P2 | 仅请求一次 `/pair.json`，没有任何手机扫码，设备数就从 1 增为 2 | 未使用的配对凭据标为待配对，限制有效期，不能计入已配对手机；重新生成应处理旧码 |
| P2 | 只读会话已明确提示“另一设备正在使用”，仍显示可点击的“结束会话” | 根据控制权隐藏或禁用写入动作；需要接管时说明步骤，不让用户先点再被服务端拒绝 |
| P2 | 设备吊销、删除和自定义内核移除在菜单中直接执行，没有确认步骤（源码核查，未点击删除） | 写明目标与影响，危险动作统一确认；历史文件删除已有确认，可复用其交互模式 |
| P2 | 代理只有启动入口；停止只在窗口关闭时调用，没有明确的停止/重启管理入口（源码核查） | 对本窗口拥有的代理提供停止操作；外部代理显示来源和管理边界，不能误杀 |
| P2 | 内核页有“本机实时读取，不是写死的清单”“会真的启动一次 ACP 握手”等面向开发者的解释 | 日常界面只留检测时间、状态、原因和操作；协议、配置文件及存储路径放详情 |
| P3 | 普通空闲会话用红色状态点；Markdown 引用显示原始 `>` | 空闲改用中性色，错误才用红色；补引用渲染或明确使用纯文本预览 |
